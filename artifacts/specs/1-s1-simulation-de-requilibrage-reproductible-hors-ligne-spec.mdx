## Context

Promu depuis l'analyse [`1-s1-simulation-de-requilibrage-reproductible-hors-ligne-analysis.mdx`](../analyses/1-s1-simulation-de-requilibrage-reproductible-hors-ligne-analysis.mdx) et le frame #1. Shape retenue : domaine en modules purs, journal absorbant les champs d'identification du contrat d'événement cible. Contrats : ADR-0001 (axe primaire capacités métier), `docs/standards/backend-patterns.md`, `docs/standards/testing.md`.

Écarts assumés par rapport à l'analyse : le fixture vit à la racine `fixtures/` (et non `tests/fixtures/`) car la CLI de démonstration et les tests lisent le même fichier versionné ; `src/config.ts` reste inchangé — cible et frais sont des objets de politique versionnés dans le code.

Gate 2.5 (splitting) : écarté — critères fortement couplés aux trois slices, appétit d'une PR unique.

## Goal

Exécuter `bun run start` sur un jeu de données synthétiques versionné produit un rapport simulé (valorisation, écarts à la cible, propositions, journal) strictement identique à chaque exécution, avec refus explicites de toute donnée invalide — refus journalisés — et aucun chemin d'ordre.

## Users

- **Primaire :** l'opérateur du dépôt, qui lance la CLI et lit le rapport pour vérifier une proposition à la main.
- **Secondaires :** les tranches S2+ (ingestion qui produira de vrais `Snapshot`, explication qui lira le `Report`), et les revues/CI qui vérifient le déterminisme et l'absence de chemin d'ordre.

## Expected Behavior

L'opérateur lance `bun run start` (one-shot ; `--input <chemin>` pour un autre jeu, défaut `fixtures/s1-synthetic-portfolio.json`). La composition charge et parse le fixture JSON, construit un `Snapshot` validé (refus typé et journalisé sinon), appelle le cas d'usage pur `simulateRebalance`, puis affiche le rapport : JSON canonique stable suivi d'un résumé texte. Deux exécutions fraîches produisent deux sorties identiques octet par octet. Aucune écriture réseau, fichier ou ordre n'a lieu ; toute sortie est étiquetée « simulated ».

## Data Model & Consumers

> **Sidecars forge non générés** (plugin forge absent de l'environnement) : `1-{slug}-data-model.html` et `1-{slug}-consumers.html` à régénérer après installation. Le modèle textuel ci-dessous fait foi jusqu'à régénération.

**Forme canonique** (utilisée par sérialisation, empreintes et identifiants) : JSON à clés triées, sans blanc, UTF-8, montants et prix en chaînes `"<units>e-<decimals>"`, tableaux triés par code d'actif. Interdits dans le rendu : `Intl`, `toLocaleString`, toute horloge murale.

Types du domaine (immuables, construits via fabriques validées ; montants et prix en unités entières `bigint` + `decimals`, jamais de flottant) :

| Type | Champs | Notes |
| --- | --- | --- |
| `AssetCode` | marque sur `string` | ex. `BTC` ; pattern `^[A-Z0-9]{2,10}$` |
| `AssetMeta` | `code, decimals, quoteCurrency` | figé ; `decimals ∈ 0..18` |
| `Amount` | `asset: AssetCode, units: bigint` | fabrique refuse les `units` négatifs ; les deltas signés sont un type distinct `SignedDelta` |
| `Price` | `asset, quote: AssetCode, units: bigint, decimals` | le prix d'une unité entière d'actif est `units × 10^-decimals` en devise de cote ; `quote` doit égaler la `quoteCurrency` de l'actif |
| `Holding` | `asset, amount: Amount` | |
| `Snapshot` | `assets: AssetMeta[], observedAt: string (ISO, issu des données), holdings, prices` | `assets` trié, codes uniques, métadonnées conflictuelles refusées ; tableaux triés par code ; tout actif détenu **ou ciblé** doit avoir un prix |
| `TargetAllocation` | `policyVersion: string, weights: {asset, weightBps}[]` | points de base entiers, somme exacte `10000`, trié par code |
| `FeePolicy` | `policyVersion, bpsPerTrade` | `bpsPerTrade` entier ≥ 0, validé en fabrique |
| `Proposal` | `kind: "simulated", asset, signedDelta, deltaValue, estimatedFee, reason` | `deltaValue` = valeur du delta en devise de cote ; `estimatedFee = troncatureVersZéro(\|deltaValue\| × bpsPerTrade ÷ 10000)` en arithmétique entière, appliquée dans les deux sens |
| `JournalEntry` | `schemaVersion, id, kind: "simulation" \| "rejection", allocationPolicyVersion, feePolicyVersion, source, inputFingerprint, observedAt, data` | `source: "s1-fixture"` ; chaque refus produit une entrée `kind: "rejection"` portant le nom du champ fautif, jamais sa valeur ; `id` = FNV-1a 64 bits pur sur la forme canonique de l'entrée **hors champ `id`** (pas d'auto-référence) ; `inputFingerprint` = même hash sur `{snapshot, target, fees}` canoniques. FNV-1a n'est pas résistant aux collisions : acceptable comme identité de rejeu S1, pas comme empreinte de contenu adverse |
| `Report` | `kind: "simulated", valuation, deviations, proposals, entries` | `deviations` par actif : poids courant (bps), poids cible (bps), écart (bps), valeur courante en devise de cote. Snapshot vide : valide, valorisation 0, poids courants définis à 0 bps, aucune proposition |

**Devise de cote unique :** toutes les `quoteCurrency` des actifs détenus ou ciblés, et toutes les `quote` des prix, partagent une seule devise ; toute divergence est refusée.

**Consumer map (textuelle) :** `src/main.ts` (composition) consomme tout ; les tests consomment le domaine et le cas d'usage ; S2 ingestion produira de futurs `Snapshot` (bordure pointillée), S3 explication lira de futurs `Report`/`JournalEntry`.

| Consommateur | Champs consommés | Quand | Statut |
| --- | --- | --- | --- |
| `src/main.ts` | `Snapshot`, `TargetAllocation`, `FeePolicy` → `Report` | à chaque exécution CLI | cette issue |
| `tests/*` | tous les types + cas d'usage | tests unitaires et e2e | cette issue |
| S2 ingestion | produira `Snapshot` | S2 | futur |
| S3 explication | lira `Report`, `JournalEntry` | S3 | futur |

## Success Criteria

- [ ] Le test e2e intra-processus exécute U1 deux fois sur F1 et les deux rapports (forme canonique JSON) sont identiques octet par octet.
- [ ] Deux exécutions CLI fraîches (sous-processus `bun src/main.ts`) produisent un stdout identique octet par octet, JSON canonique et résumé texte compris.
- [ ] Un actif détenu ou ciblé sans prix produit `MissingPriceError` citant l'actif, sans rapport produit.
- [ ] Un champ absent du fixture produit `MissingFieldError` citant le champ, sans valeur affichée.
- [ ] Un prix coté dans une devise ≠ `quoteCurrency` de l'actif produit `QuoteMismatchError` ; un snapshot mêlant deux devises de cote produit `MixedQuoteCurrencyError`.
- [ ] Deux montants d'échelles incompatibles présentés à une opération produisent `ScaleMismatchError` (jamais de mélange silencieux).
- [ ] Tout refus est journalisé en entrée `kind: "rejection"` (champ fautif, sans valeur) ; les résultats sont journalisés en entrée `kind: "simulation"` ; chaque entrée porte `schemaVersion`, `allocationPolicyVersion`, `feePolicyVersion`, `source`, `inputFingerprint` et un `id` FNV-1a reproductible calculé hors `id`.
- [ ] Toute `Proposal` et tout `Report` portent `kind: "simulated"` ; le rapport expose par actif poids courant/cible/écart en bps et valeur courante, et par proposition le delta en unités **et** en valeur plus le taux de frais appliqué.
- [ ] Des poids sommant ≠ 10000 bps sont refusés à la fabrique ; un `bpsPerTrade` négatif ou non entier est refusé.
- [ ] Un snapshot vide est valide : valorisation 0, poids courants 0 bps, aucune proposition.
- [ ] Un test statique vérifie zéro occurrence de `node:http`, `node:https`, `node:net`, `node:fs`, `node:child_process`, `fetch(`, `XMLHttpRequest`, `spawn(`, `process.env`, `Bun.env`, `Intl`, `toLocaleString` dans `src/domain` et `src/app`.
- [ ] `bun run check`, `bun run license:check` et `bun run secrets:check --all` passent ; `src/config.ts` est inchangé ; zéro dépendance runtime ajoutée.
